Stack

Main runtime

  • Electron for app shell, IPC, window management, and packaging.
  • TypeScript in `src/main.ts` and `src/preload.ts` for the privileged side.
  • `electron-store` for local persistent app state.

Monitoring and setup

  • `@ibm/mapepire-js` for IBM i connectivity through Mapepire.
  • `ssh2` for remote detect, start, and deploy flows.
  • Generated local demo snapshots for development-only monitoring behavior.

Runtime ownership

Area Owns Should avoid
Main process Connection lifecycle, Mapepire setup, monitoring state, alert state, logs, IPC handlers, guidance payloads, and job actions Renderer-only presentation concerns
Preload Safe API bridge between UI and privileged code Business rules and state mutation logic
Renderer UI rendering, event handlers, page-level state, user feedback, job drawer guidance, and operator actions Direct access to Node or Electron internals

Current feature foundations

Operator actions

`src/features/operator-actions/operator-actions.ts` defines supported IBM i job actions and execution plans.

History reconstruction

`src/features/history/history-model.ts` parses structured `.jsonl` logs and rebuilds trend series and incident markers.

Root-cause guidance

`src/features/guidance/root-cause-guidance.ts` explains waits, high CPU, and monitoring failures for operators.

Current gap

Real `MSGW` reply still needs safe IBM i message-level context in the job detail path.

Important boundaries

  • Demo mode stays development-only and should remain easy to remove from packaged builds.
  • Feature logic should keep moving out of `src/main.ts` into dedicated modules.
  • Renderer pages should gradually move toward their own source modules instead of large page scripts.
  • Persistent logs should remain structured enough to power future history and incident replay.

Next refactor targets

  1. Split `src/main.ts` into focused areas for store, IPC, and runtime orchestration.
  2. Move renderer page logic into clearer renderer feature modules.
  3. Reduce global mutable state in the main process.
  4. Keep demo generation and production monitoring decoupled.
  5. Extend job detail fetches with IBM i message-level context for real `MSGW` replies.
